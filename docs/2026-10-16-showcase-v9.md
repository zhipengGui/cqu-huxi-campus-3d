Ruling: 聊天内方案已经批准，本文记录执行和验收，不再要求用户重复批准同一范围。采用既有本地分支 + 工作区镜像，Windows 下以原生命令维护账本，不增加 shell 工作流依赖。判断错误的代价是需要回滚相关本地提交，v8 分支仍可恢复。
Ruling: 新增业务几何以有意义的失败回归驱动；可逆的材质和 CSS 调整通过实际截图/交互验证，不编写镜像实现的测试。

## 参考及已知问题

GXU dev GitHub 的 basketball.py、sports_data.py 已核对，参考仓库截图标注 2026-10-12。虎溪体育设施和校园图官方页面本次均返回 412，不能宣称已从页面核准场地。既有 OSM 数据含 14 片独立篮球场、5 片网球场、20 片羽毛球场、5 片足球场，以及其它场地；大型集合面需避免与单片场地重复建模。原始输入/导航不改。

## 验证与裁定记录

基线 test_context.mts、test_views.mts 均通过。M11 新增 test_sports.mts 首次失败于篮球面层超出真实轮廓；修复后，三个旋转方向的面层、横向中线、篮圈位置、其它场地面层、输入不变及预算均通过。体育区共 16 次绘制、49,709 个三角形；实际场地统计区分 14 个篮球场与 1 个未细分场区。TypeScript/生产构建通过，浏览器控制台无错误。固定机位修改前后图保存在 work/qa/v9-before-* 与 docs/screenshots/v9-m11-*。

Ruling: 本轮使用现有 Three.js 参数化体育模型统一几何，不把全部球场改为 Blender 资产——同一布局可直接验证，减少重建和加载成本；若未来需要实测复杂看台再单独建资产。
Ruling: 大型篮球集合面与乒乓球集合面只保留铺装，不擅自猜数量；未分类运动用地保留原轮廓，不添加未证实的跑道或设施。代价是待证据区域细节较少，已有体育区可以先独立验收。

桌面自动画质目标 45 FPS，手机目标 30 FPS；须注明设备、分辨率和测试方式，浏览器模拟不能冒称实体手机实测。

M12：用户明确“田径场就在体育馆旁边那个足球场外面围了一圈跑道”，结合体育馆及足球场相对位置确定 OSM 1057532743；配置只匹配该 ID，其他大块地仍不推断。田径场缺失及跑道与足球角点重叠均先复现后修复；树木体育用地避让测试也先失败后通过。体育模型共 19 次绘制 / 53,251 三角形，整幅体育区实际渲染约 867,651 三角形，相比 M11 减少（绿化收敛），示意树木由 2,326 株调整为约 1,770 株。浏览器四个地标/湖区及体育固定机位无错误，既有 GLB 未重建。

Ruling: 用户确认的是跑道归属和位置；98×180m 的布局包络、八道和 1.22m 道宽仍是轮廓/间距约束下的建模估算，不是实测或认证 400m 跑道。配置位于 sports.ts 的 VERIFIED_TRACK，足球场原位置和方向保留；若估算需校准，仅调整此场区。
Ruling: 共享铺装仅在已映射的未分类场区轮廓包含多个已确认球场时补示意面层；保留原导航图。大草地不再按面积直接当森林加密，树木仍是示意分布。代价是个别铺装材质与种植细节需要实照继续校准。

M13：校区身份/体育入口浏览器检查先失败后通过；新增“田径场”“室外球场区”两处搜索/详情/定位，前往按钮使用当前所选地点而非巡游索引。手机默认收起列表但保留三个快捷入口，更多菜单包含缩放/分享/导出/全屏；详情展开和四栋建筑取景通过。原有导航、选择、昼夜、近档延迟加载、搜索、图层、院落开口回归通过，桌面有效视区占宽 81.13%。2.2 秒桌面 DPR 1 短采样约 41.8 FPS，未达到 45 FPS 目标，M14 将优化反复渲染的静态阴影并复测；不能将功能回归通过写成性能达标。
