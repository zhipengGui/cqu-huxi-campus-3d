## 全局约束

- 现有 Three.js 0.170 / TS / Vite，不引入 React、动画或物理引擎依赖；模型与现有原始路网不改。
- M15 路径计算与入口接入；M16 导航操作；M17 桌面第一人称与基础碰撞。GPS、自动跟随、室内、手机自由步行属于后续批次。
- 入口未获现场证据，一律“附近道路”，不能把楼中心或模型门洞标成已核实入口。
- 操作原有搜索、地标、图层、昼夜、巡游、分享、导出及手机兼容；只本地候选分支验收，不自动推送新功能。

## 复核关注

1. 同边反向、零长边、边权取整、断图；不能切角或返回错误最短路。
2. 未核实入口、湖泊与远处地图点；不能伪装真实入口或无条件穿越障碍。
3. Pointer Lock 失败、失焦与连续切换；相机和按键必须可恢复。
4. 已有侧栏 view offset、resize、巡游与分享；不能与步行抢相机或留下近裁面。
5. 穿模、院落洞、门洞未知与水边；碰撞必须匹配已声明的简化范围，不承诺室内/真实坡道。

## M17 步行实现与复核

碰撞世界先以缺模块测试失败，随后建筑/水面/校界、半径间距、斜向滑墙、长步长防穿越、真实院落洞、仅道路/铺装可行及数据不可变全部通过。四处真实地标均找到 100m 范围内的可步行点。默认眼高 1.65m、步速 1.4m/s、身体半径 0.3m；32m 网格只查询邻近轮廓，按半径细分移动，无新增运行依赖。

Pointer Lock 浏览器专项先因缺少入口失败，实现后取得真实锁定；发现 Three.js r170 的 lock() 不传递 Promise，改为捕获浏览器原生 requestPointerLock 的同步和异步失败。又以进入后立即退出复现异步锁定残留，增加 lock 事件守卫后回归通过。退出、失焦、锁定拒绝及漫游期间 resize 均恢复 Orbit 相机和投影。

视觉检查发现“最近道路切线”在交叉口可能指向立面，一教的自动接近点还位于建筑内部道路，初始视野过近。因此最终用 `data/walk_spawns.json` 指定四个室外位置和朝向（场景核对，不冒充现场核实入口）；新增配置测试先 RED，四处可行与初始1m道路移动 GREEN，再用真实 Pointer Lock 截图和移动复查。最终一教沿楼外道路朝湖区展开，图书馆沿外侧道路展开。

独立整分支复核一次，Critical 0、Important 3、Minor 1；逐项核实后 Important 评级全部接受，仅做一轮修复，不再启动重复复核：

- fixed：已有路线误点远处会丢两端点。测试实际 RED（260m 路线变 null）→先验证吸附再替换，原路线/起终点引用保持，GREEN。
- fixed：选择占位项后仍保留旧端点。浏览器断言占位项禁用先 RED→禁止再次选择占位项，选择失败后刷新状态，GREEN。
- fixed：两个坐标相同但 ID 不同的节点间零长边被丢弃。10m 连接反例实际 RED（null）→保留邻接连接，仅排除几何吸附与除零计算，GREEN。当前真实数据无此类边。
- minor (deferred)：湖泊可从详情设置导航，但端点选择器暂未包含 water 选项，会显示空值；下方仍显示正确附近道路说明。后续统一所有地点入口与选择器规则，本轮不扩大修复范围。
- minor (inherited/deferred)：v9 泳池斜边标线和历史 Python 院落内缩采样差异沿用原记录，本轮未改模型或体育几何。

Final Ruling：复核没有裁定真实道路开放、门禁、台阶和无障碍通行，因为缺乏现场证据；原路网与附近道路只用于展示和图上路径，不构成已核实通行承诺。GPS、室内、真实高程、手机自由步行均属后续批次，未以其缺失阻塞本批。
Final Ruling：基础碰撞按建筑轮廓、水面和校界计算，院落洞保持，未知门洞不猜可穿越；树木、GLB 装饰、体育器材尚不做逐网格碰撞。代价是室外地图漫游仍属于简化体验，不能宣称完整物理世界。
Final Ruling：旧浏览器导航用例在选目的地、再选地图起点后已经生成路线并自动取景；删除其再次点击旧屏幕坐标的步骤。旧坐标在相机移动后不再代表原建筑，此调整验证实际新流程，并非放宽路线断言。一次立面取景即时断言曾失败，保留诊断值后未改产品代码，完整重跑通过；不能把该次失败记作通过。
Final Ruling：复核未独立运行的完整浏览器和生产检查由父执行者完成；手机只以 390×844 浏览器模拟验证，实体设备帧率仍未实测。保留构建包 >500KB 提示，不为消除提示新增拆包框架。
Final Ruling：四处漫游使用人工配置的场景道路出生点与朝向，替代不稳定的最近边自动推导；楼门接近点仍独立保留。代价是未来更新道路或模型后需重新核对四处画面与初始通行，不声称现场测绘。
