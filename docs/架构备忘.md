## 技术栈

2026-10-16 v8 补充：`context.ts` 在 200m 范围内生成合并后的周边体块与地表，地表跨范围时裁切保留附近部分，受 20 次绘制/50k 三角形硬预算约束。`campusClip.ts` 的边段距离与带圆角缓冲裁路只影响视觉；校内面积要素统一筛选，运动场不再按面积猜跑道。`landmarkViews.ts/framePoints` 将实际校园点集拟合进侧栏之外的视区；新模型导出 courtRadius，近景按院落尺寸定位。见 [v8 记录](2026-10-16-context-v8.md)。

2026-10-16 v7 补充：地标配置 `data/landmark_details.json`，生成器 `scripts/blender/build_priority.py` / `build_gates.py`，旧 `build_models.py` 仅作转发。地标按原 OSM 包围盒中心定位，不改变原方位；远近档 Draco GLB 配本地解码器，失败保留 TS 回退。`landmarkViews.ts` 根据完整资产和物理相机投影取景，`campusClip.ts` 只裁视觉道路，原导航图不变。当前分支未部署，具体限制和验证见 [v7 记录](2026-10-16-landmarks-v7.md)。

- 前端：Vite + TypeScript + Three.js（纯前端静态站点，无后端、无地图密钥）
- 数据：OpenStreetMap（ODbL，页面需署名 © OpenStreetMap 贡献者）
- 离线管线：Python 3.13 标准库（无第三方依赖）

## 核心架构（学 gxu：数据驱动，接口只碰一次）

```
OSM API/Overpass ──▶ data/snapshots/osm_snapshot_*.json（进 git，一次拉取永久使用）
                        │ scripts/build_scene_data.py
                        ▼
                 public/data/scene.json（局部米制坐标 + 楼栋属性）
                        │ src/main.ts + sceneBuilder.ts
                        ▼
                 Three.js 场景（ExtrudeGeometry 楼块 / 道路条带 / 水面绿地）
```

- 坐标：WGS84 → 以 bbox 中心 (106.295, 29.595) 为原点的局部米制坐标，X 东 / Y 北；
  前端映射 x=东、z=-北、y=高（sceneBuilder.ts 顶部有约定注释）
- 高度：OSM `height` 标签 > `building:levels`×3.3m > 按占地面积默认层数（≥5000㎡:5 层，
  ≥2000:4，≥800:3，其余 2）。人工校准走 `data/height_overrides.json`（M2 引入）

## v2 精细化轮（2026-10-14 完成，对标 gxu-campus-3d 验收）

用户反馈"白方块太糙、道路不明显、要做导航"→ 方案 C 过审（three.js 程序化立面 + 参数化地标，导航直接做）：

- **立面系统**（src/facades.ts + sceneBuilder）：管线 classify_style 七类楼型；
  Canvas 自制窗带 tile（一 tile = 一层 3.3m×8m），clone 纹理 repeat(1, floors)；
  rewriteFacadeUV 把侧面 v 按真实高度/3.3m 对齐、u 按轮廓周长展开；
  女儿墙全城合批 1 mesh，屋顶设备块合批 1 mesh
- **道路**：major/campus/path 三级，沥青 #50555b + 人行道衬带(+3m) + 主路中央虚线，
  各自合批（4 draw call）；地面换草绿；湖岸外扩 1.6m 沙色环带；操场按 sport 分色；泳池/跑道新类
- **地标精模**（src/landmarks.ts，参考实拍照片 work/refs/）：图书馆=真实轮廓裙楼（玻璃底座+
  红棕上段）+居中窄长百叶板塔（fin 纹理）+塔顶"重庆大学"红字；学生活动中心=轮廓拉伸三段
  （玻璃底座/白墙/白冠带）；校门=白横梁+红校名+徽标+门柱翼墙，管线从 barrier=gate 节点
  取位（950m 内、180m 去重、按方位命名东/西/南/北门）
- **步行导航**（src/navigation.ts）：管线 build_graph（0.5m 网格去重节点+dedup 边，排除
  trunk/motorway/steps）；前端 A*（二叉堆），起终点吸附最近边按 t 拆分代价的多源虚拟起终点；
  CatmullRom+TubeGeometry 橙色路线；距离/步时（80m/min）
- 验收实测：宿舍窗带网格/图书馆塔顶校名/东门门楼/905m 路线+11 分钟均通过；390 draw calls / 240 FPS

**v2 踩坑记录（重要）**：
1. ExtrudeGeometry 材质分组 **0=顶底面、1=侧面**（与直觉相反）——写反会导致"窗带贴屋顶、墙面纯素色"
2. 通用楼 mesh.position=(0,0,0)（几何携带绝对坐标）——调试定位要用 userData.cx/cy，别用 getWorldPosition
3. 地标组"烘焙世界矩阵到子网格"的方案丢了子对象偏移（塔沉入地）——直接返回带变换的 Group + 递归射线拾取
4. OSM 里有两栋"图书馆"（另一栋在 2.3km 外属别校）——landmark 标记必须加校区范围守卫
5. CSS2D 标签点击别用 Playwright（每帧 transform 变化永不"稳定"），用 cua 坐标（getBoundingClientRect 查）

## v3 校界裁剪 + Blender 精模轮（2026-10-14 完成）

用户验收反馈：西南角那片不是重大（川美等混入）、富力假日酒店不该出现、
大建筑要 Blender 精模、每座校门应各不相同。先反问确认四项裁决：
校外 gxu 式淡背景 / 精模 5 栋（工科+信息+体育+图书馆+活动中心）/ 真三门 北东南 / Blender 便携版装 D 盘。

- **校界裁剪**：边界 = OSM way 239537195（amenity=university），管线打 inside 标记，
  校外 name 置空 + 前端合并为单个淡灰网格（无标注/无拾取）；白校界线 LineLoop；
  地点 73→47 全部真实。假名黑名单实锤：罗中立美术馆/雕塑系=川美，逸夫图书馆=重师，
  富力假日酒店=酒店，三乐大礼堂/明远教学楼等=校外错误命名
- **校门重定**：公开资料 北门（大学城南路55号）/东门/南门三门；北门/东门用 OSM barrier
  节点匹配，南门取校界最南点最近道路推导（**注：v3 之后 56ad260 已按用户确认为真三门 北/东/西门**）
- **Blender 管线**（scripts/blender/build_models.py）：
  `<blender> -b --python ... -- --asset <name|all>` → Cycles CPU 预览图 + GLB 导出
  （public/models/）。资产：library/info/gym/gongke/activity + gate_east/north/west。
  Blender 4.5.9 LTS 便携版在 D:\tools（TUNA 镜像下载，官方目录列表 403 但直链可用）
- **前端集成**：GLTFLoader，landmark/gate 优先 GLB（约定：建筑原点=轮廓中心、
  长轴 X、Z-up→Y-up 由导出器处理，three 里直接 position (cx,0,-cy) 零旋转；
  门原点=门位点、横梁沿局部 X、rotation.y = 角度+π/2），失败自动回落 TS 参数化
- 参考：重大官网"光影重大"14 页图集（gyzd.htm、gyzd/13.htm…），
  东门=四石柱门柱广场、北门=复刻老校门白穿孔板、信息大楼=白框架网格、
  体育中心=弧形肋金属屋顶+红砖基座、活动中心=锈红新月
- **Blender 踩坑**：① 混合"绝对坐标网格+location 对象"时 recenter 一刀切会甩飞局部
  坐标网格（gym 拱顶消失）——规则：网格数据一律烘绝对坐标或一律 location；
  ② gym 首选自动挑中整个田径场区（leisure=sports_centre 场地多边形）——
  馆体候选要加 bbox 对角线约束；③ 双面校名文字太高会从侧面露出镜像穿帮——贴冠带布置
- IAB 截图通道在本会话后期持续超时（新标签/视口重置均无效），后期验收改用
  Blender 预览图 + 少量关键截图，其余由用户浏览器自验
